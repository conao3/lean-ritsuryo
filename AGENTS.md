# AGENTS.md

`lean-ritsuryo` computes Japanese statutory periods (民法 140〜143 条, 国税通則法 10 条, 民事訴訟法 95 条, 年齢計算ニ関スル法律, 祝日法) and taxes (所得税法 89 条, 相続税法 15・16 条, 消費税, 延滞税・利子税, 加算税, 国税通則法 118・119 条) in Lean 4, with proofs attached to the functions the CLI runs. The Lake package and the CLI are `ritsuryo`; the root namespace is `Ritsuryo`.

## Layout

- `Ritsuryo/Law.lean`: the statutes referenced by the library, with their e-Gov law IDs.
- `Ritsuryo/Basis.lean`: the `@[ritsuryo_basis "<statute>" "<provision>"]` and `@[ritsuryo_proof "<ID>"]` attributes. Library modules load it with `meta import`, so the CLI binary does not link `Lean`.
- `Ritsuryo/Calendar/`: dates, day numbers, weekdays, and the CAL proofs.
- `Ritsuryo/Period/Spec/`: definitions that copy the provisions (民法 138〜143 条・142 条, 民事訴訟法 95 条, 国税通則法 10 条). `Impl.lean`, `Age.lean`, `Rollover.lean` hold what the CLI runs; `Presets.lean` holds 控訴・上告・即時抗告 and the 所得税 return deadline; `Proofs/` proves PER, AGE, ROL.
- `Ritsuryo/Holiday/`: 祝日法 2 条・3 条 (`Spec.lean`, `Proofs.lean`), the CSV tables (`Data/Generated.lean`, generated by `scripts/gen_holidays.py` from `data/syukujitsu.csv`; do not edit by hand), lookup and the era-aware derivation (`Lookup.lean`), the HOL-C1 check (`Check.lean`), and 第2条 as rules with their periods in force plus the HOL-C2 check (`Article2.lean`, `Article2Check.lean`).
- `Ritsuryo/Tax/`: 国税通則法 118・119 条 rounding (`Rounding.lean`), the bracket table shared by 所得税 and 相続税 (`Progressive.lean`), `Income.lean`, `Inheritance.lean`, `Consumption.lean`, `Delinquency.lean` (延滞税・利子税), `Penalty.lean` (加算税), and `Proofs/` (TAX, RND, CON, DEL, PEN, INH).
- `Ritsuryo/Cli/`: JSON, argument parsing, `--query` (JMESPath, `Query.lean`), rendering, the output envelope, and the command table (`Period.lean` and `Tax.lean` hold the subcommands, `Commands.lean` joins them). `Main.lean` is the `ritsuryo` entry point.
- `Ritsuryo/Audit.lean` and `BasisReport.lean`: `lake exe basis-report` renders `docs/basis.md`; `--check` fails on a public definition under `Ritsuryo.Calendar`, `Ritsuryo.Period`, `Ritsuryo.Holiday`, or `Ritsuryo.Tax` without a basis, a theorem using an axiom other than `propext`, `Classical.choice`, `Quot.sound`, or a design ID with no theorem.
- `Tests/`, `TestMain.lean`: library tests run by `lake test` (worked examples and the Std.Time differential test). `scripts/test_cli.py` tests the built CLI.
- `docs/interpretation.md`: how each provision is read. Update it when a spec changes.

## Conventions

- Every library file is a `module`. Definition files use `@[expose] public section` so proofs in other modules can unfold them; library code loads `Ritsuryo.Basis` with `meta import`.
- Each public definition under `Ritsuryo.Calendar`, `Ritsuryo.Period`, `Ritsuryo.Holiday`, and `Ritsuryo.Tax` carries `@[ritsuryo_basis]`. Each theorem listed in the design carries `@[ritsuryo_proof "<ID>"]`.
- Proofs use core tactics only (`omega`, `decide`, `simp`, `grind`). `sorry`, `admit`, and `native_decide` do not appear in theorems.
- Source comments are written for readers of the code, in Japanese. Each file starts with a module docstring (`/-! … -/`) that says which statute it implements, quotes the provisions from e-Gov with the revision ID, and says which definitions are the spec, which the CLI runs, and which theorem ties them together. Each definition and theorem has a docstring saying what it computes or states (for theorems, also how the proof goes). A docstring that quotes a provision keeps the quote verbatim and adds the explanation after it. Line comments (`--`) are kept to steps that are not obvious.
- Commit messages, README, and `docs/` are in English. Statute quotes and CLI output strings stay in Japanese.

## Verification

Run everything inside the devShell:

```console
$ nix develop --command make check
$ nix build
```

After adding or renaming a `.lean` file, run `git add -N <file>` before `nix build` (the flake only sees tracked files). After changing an attribute, regenerate the report with `make basis`.
